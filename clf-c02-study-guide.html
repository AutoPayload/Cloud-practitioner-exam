How the questions work and how to beat them

Exam skills

Knowing the services is half of the job. The other half is reading each question the way it was written: find what is really asked, spot the word that decides the answer, and eliminate the traps. This page teaches that skill.

How the exam is scored

  • 65 questions in 90 minutes. 50 are scored. 15 are unscored trial questions that AWS is testing for future exams. You can't tell which ones they are, so if a question looks strange, don't panic: it may not count.
  • Scaled score from 100 to 1,000; you pass at 700. The exam is compensatory: you pass on your total score, not on each domain.
  • No penalty for guessing. A blank answer counts as wrong, so answer every question.
  • Multiple-response questions give no partial credit. You must pick all the correct options.

The two question types

Multiple choice

One correct answer and three distractors. Most questions are this type. In this guide, square letter buttons mean “pick one” and round ones mean “pick several.”

Multiple response

Two (sometimes more) correct answers out of five or more options. The question says (Select TWO.). Each correct option must be true by itself. The exam won't warn you if you pick the wrong number.

Anatomy of a question

Almost every question has the same three parts. Colour them in your head as you read.

A company runs its web application on Amazon EC2 instances in a single Availability Zone. The company wants the application to stay available if that Availability Zone fails. Which solution meets this requirement with the LEAST operational overhead?

Scenario: background, often with details that don't matterRequirement: what must be trueQualifier: how to choose between answers that work

Here several answers could work (run a second copy by hand, write scripts, use an Auto Scaling group across two AZs behind a load balancer). The qualifier least operational overhead picks the managed, automatic option: an Auto Scaling group across multiple AZs with an Elastic Load Balancer.

Answer any question in five steps

  1. Read the last sentence first. It tells you what is being asked: a service, a responsibility, a benefit, a cost option.
  2. Find the requirement and the qualifier. Say them in four or five words: “survive AZ failure, least effort.”
  3. Predict the answer before you read the options. If your prediction is there, it is probably right.
  4. Eliminate. Cross out options from the wrong category (a database for a networking need), services that don't do that job, answers that are true but don't answer the question, and over-engineered solutions.
  5. Choose the simplest AWS-managed option that meets every requirement. If you are still unsure after about a minute, pick your best guess, flag it, and move on.

Worked examples

Try each one before you open the walk-through.

1A company runs MySQL on Amazon EC2. The team spends hours every month on OS patches, database patches and backups. Which change reduces this work the MOST? A. Move to a larger EC2 instance · B. Migrate to Amazon RDS for MySQL · C. Buy a Reserved Instance · D. Use EC2 User Data to install patches
  1. Asked: a way to reduce operational work.
  2. Requirement: less patching and backup effort. Qualifier: MOST.
  3. Predict: a managed database.
  4. Eliminate: A adds power, not less work. C lowers cost, not work. D only runs at first boot.
  5. Answer: B. RDS automates OS and engine patching and backups. This is also the Replatform migration strategy.
2According to the AWS shared responsibility model, which of the following is the customer's responsibility when using Amazon RDS? A. Patching the database engine · B. Managing the underlying host · C. Configuring security group rules that control database access · D. Replacing failed storage
  1. Asked: a customer responsibility for a managed service.
  2. Rule: if you configure it, it's yours.
  3. Eliminate: A, B and D are done by AWS for RDS.
  4. Answer: C. Network access rules, database users and the encryption setting stay with the customer.
3Which actions should a company take to protect its AWS account root user? (Select TWO.) A. Enable MFA on the root user · B. Share the root password with the admin team · C. Delete any root user access keys · D. Use the root user for daily administration · E. Attach an IAM policy to the root user
  1. Multiple response: exactly two answers, each correct by itself.
  2. B and D break best practices. E is impossible: you can't attach IAM policies to the root user.
  3. Answer: A and C. Protect root with MFA and don't keep access keys for it.
4A company runs nightly image-processing jobs. The jobs can be stopped and restarted at any time. Which EC2 purchasing option is the MOST cost-effective? A. On-Demand · B. Spot Instances · C. Dedicated Hosts · D. 3-year Reserved Instances
  1. Qualifier: MOST cost-effective. Key detail: can be interrupted.
  2. “Can be interrupted” plus “cheapest” always points to Spot (up to 90% off).
  3. RIs need steady 24/7 use; Dedicated Hosts are the most expensive.
  4. Answer: B.
5Which of the following is NOT a benefit of AWS Organizations consolidated billing? A. One bill for all accounts · B. Combined usage for volume discounts · C. Sharing Reserved Instance discounts · D. Automatic encryption of all member accounts' data
  1. NOT question: find the false one.
  2. A, B and C are the three classic benefits of consolidated billing.
  3. Answer: D. Billing has nothing to do with encryption.

Traps to watch for

  • Look-alike names: CloudTrail, CloudWatch, CloudFormation, CloudFront; Inspector and GuardDuty; Shield and WAF; Transcribe, Translate and Textract. Say what each does before you choose.
  • A real service used for the wrong job: Snowball for a transfer that takes hours online, Direct Connect when the company needs a connection today, Glacier for data read every day.
  • Over-engineered answers: a working but complicated solution is usually wrong at this level. AWS prefers the managed feature built for the job.
  • Swapped responsibilities: options where the customer patches the hypervisor, or AWS configures your security groups.
  • Absolute words like “always,” “never,” “all,” “guarantees 100%” are usually wrong.
  • Retired or closed products such as CodeStar and Snowcone (retired), Cloud9 (closed to new customers), and previous-generation options such as the Classic Load Balancer are not good answers for new designs.
  • Exact percentages are rarely the point. Know the order (Spot is cheapest), not the decimals.

Cloud concepts and economics

Cloud computing is renting IT (servers, storage, databases, software) over the internet and paying only for what you use. AWS owns and runs the hardware. You create and delete resources in minutes, whenever you need them.

The five characteristics of cloud computing

CharacteristicWhat it means in plain words
On-demand self-serviceYou create resources yourself, any time, without calling or emailing the provider.
Broad network accessYou reach the resources over the network from any device: laptop, phone, server.
Multi-tenancy and resource poolingMany customers share the same physical hardware, but each one is isolated and private.
Rapid elasticity and scalabilityResources grow and shrink quickly and automatically with demand.
Measured serviceUsage is metered, so you pay exactly for what you used.

The six advantages of cloud computing

This list is tested almost word for word. Learn to recognize each one from a short story.

AdvantageThe story the exam tells

Benefit from massive economies of scale“AWS is huge, so its prices are lower than we could get alone.”
Stop guessing capacity“We bought servers for our peak week and they sat idle the rest of the year.”
Increase speed and agility“Developers get a new environment in minutes, not weeks.”
Stop spending money running and maintaining data centers“We want our staff to work on our product, not on racking and cooling servers.”
Go global in minutes“We want low latency for users in Europe and Asia by next week.”

Deployment models

Public cloud

Run by a provider such as AWS and used over the internet. It delivers all six advantages.

Private cloud

Used by one organization only and not exposed to the public. Full control, but none of the economies of scale.

Hybrid cloud

Part stays on premises and part runs in the cloud, connected together. It is common during long migrations or for compliance.

Service models: who manages what

Each model moves more layers from you to the provider. The more the provider manages, the less you control and the less you have to operate.

Scalability, elasticity, high availability and agility

  • Vertical scaling (scale up or down): make one instance bigger, for example t2.micro → t2.large. It is common for databases and is limited by hardware.
  • Horizontal scaling (scale out or in): add or remove instances. It is how modern web apps scale, using an Auto Scaling group and a load balancer.
  • Elasticity: scaling that happens automatically with demand, so you pay only for what you need at each moment.
  • High availability: the app keeps running when a data center fails. The minimum is running in at least two Availability Zones.
  • Fault tolerance: the system keeps working with no interruption even when a component fails. It is a stronger promise than high availability.
  • Agility: new resources are a click away, so experimenting is fast and cheap. This is about speed, not about load.

Cloud economics

  • You pay for three things: compute time, data stored, and data transferred out. Data transferred in is free.
  • Fixed vs variable costs: on premises you buy hardware up front (a fixed cost you pay even when it sits idle). On AWS most costs are variable and follow usage.
  • Total cost of ownership (TCO): on premises you also pay for power, cooling, rent, hardware refreshes and the staff who run them. The cloud removes most of these indirect costs.
  • Licensing: either license included (the software cost is part of the hourly price) or bring your own license (BYOL, reuse licenses you already own; server-bound licenses often need Dedicated Hosts).
  • Right sizing: pick the smallest instance that does the job, and keep checking. It is the easiest way to cut costs.
  • Managed services and automation reduce operational cost, because AWS does the patching, backups and scaling.

Well-Architected Framework

AWS's checklist for building good systems in the cloud. It has six pillars. Exam questions describe a practice and ask which pillar it belongs to, so learn the keywords of each pillar.

General design principles

  • Stop guessing capacity. Test systems at production scale.
  • Automate to make experiments easy. Allow evolutionary architectures that change over time.
  • Drive architectures with data. Improve through game days (simulated events such as a flash sale).
  • Cloud design principles: scalability, disposable resources (servers are replaceable), automation, loose coupling (a failure in one part doesn't break the rest), and services, not servers (prefer managed services).

Tools

  • AWS Well-Architected Tool: free. You answer questions about a workload and get a report of risks per pillar with advice.
  • AWS Customer Carbon Footprint Tool: tracks and forecasts the carbon emissions of your AWS usage.

Cloud adoption and migration

How a company moves to AWS. The Cloud Adoption Framework (CAF) organizes the people and process side. The 7 Rs are the options for each application. A set of migration services does the technical work.

AWS Cloud Adoption Framework (CAF): six perspectives

Business perspectives

Business: cloud investments drive business outcomes. People: culture, organizational structure, leadership, workforce and training. Governance: orchestrate initiatives, maximize benefits, minimize risk.

Technical perspectives

Platform: build a scalable hybrid cloud platform and modernize workloads. Security: confidentiality, integrity and availability of data and workloads. Operations: deliver cloud services at the level the business needs.

  • Transformation domains: Technology, Process, Organization, Product.
  • Transformation phases, in order: Envision (find opportunities) → Align (find capability gaps, create an action plan) → Launch (pilots in production) → Scale (expand the pilots).
  • Business outcomes AWS promises: reduced business risk, improved ESG (environmental, social and governance) performance, increased revenue, increased operational efficiency.

Shared responsibility model

Security on AWS is split in two. AWS secures the cloud itself: the buildings, hardware and global network. You secure what you put in the cloud: your data, your users, your settings. This model is behind many exam questions.

Don't confuse

Encryption and secrets

Encryption protects data when it is stored (at rest) and when it moves across the network (in transit). On the exam, the word “encryption” usually points to AWS KMS. Certificates for HTTPS come from ACM, and passwords belong in Secrets Manager or Parameter Store.

Key facts

  • At rest: data on a disk, in S3, in a database or an archive. In transit: data moving over the network, protected with TLS (HTTPS).
  • Encryption on by default: CloudTrail logs, S3 Glacier storage classes, Storage Gateway, and since 2023 every new S3 object (SSE-S3).
  • Opt-in encryption: EBS volumes, RDS, EFS, and SSE-KMS for S3. (Your notes also list Redshift; since January 2025 new Redshift warehouses are encrypted by default, but older exam questions may still treat it as opt-in.)
  • S3 options: SSE-S3 (default, S3-managed keys), SSE-KMS (KMS keys with audit trail), SSE-C (your own key sent with each request), client-side (you encrypt before upload).

Global infrastructure

AWS is built from Regions, and each Region contains several Availability Zones. Edge locations around the world bring content close to users. Local Zones, Wavelength and Outposts extend AWS closer to cities, 5G networks and your own data center.

Key facts

  • Region: a geographic area with a cluster of data centers, named like us-east-1. Most services are Regional. Your data never leaves a Region unless you move it.
  • Choosing a Region: (1) compliance and data residency, (2) latency to your users, (3) which services are available there, (4) price.
  • Availability Zone (AZ): one or more separate data centers with their own power and networking. A Region usually has 3 (minimum 3, maximum 6). Running in two or more AZs gives high availability.
  • Edge locations (points of presence): 400+ sites that cache content (CloudFront) and answer DNS (Route 53) close to users.
  • Global services: IAM, Route 53, CloudFront, WAF (for CloudFront). Everything else you create in a Region.
  • AWS Local Zones: AWS compute and storage placed near a large city for single-digit millisecond latency. They extend a Region.
  • AWS Wavelength: AWS compute inside telecom 5G networks for ultra-low latency to mobile devices.
  • AWS Outposts: AWS-managed racks installed in your data center, with the same APIs and tools. You handle the rack's physical security.

Designing for failure

ArchitectureSurvivesTrade-off

Disaster recovery strategies, from cheapest and slowest to most expensive and fastest: Backup and restore → Pilot light (core pieces running, like a live database copy) → Warm standby (a full copy running at small size) → Multi-site active-active (full size in two Regions). DNS, content delivery and edge

These services make a global application fast and resilient. Route 53 tells users where to go. CloudFront caches content near them. Global Accelerator routes their traffic over the AWS network.

Amazon Route 53 (DNS)

  • Managed DNS and domain registration. Translates names like app.example.com into IP addresses. It is a global service with health checks.
  • Records: A (name → IPv4), AAAA (name → IPv6), CNAME (name → another name), Alias (name → AWS resource such as a load balancer, CloudFront or S3 website).
  • Routing policies: Simple, Weighted (split traffic 70/30), Latency-based (send users to the fastest Region), Failover (health check fails → go to the backup), plus Geolocation, Geoproximity and Multivalue.

Amazon CloudFront (CDN)

  • Caches content at 400+ edge locations so users download it from nearby. It is good for images, video, static sites and APIs.
  • Origins: an S3 bucket (protected with Origin Access Control so only CloudFront can read it), a load balancer, EC2, or any HTTP server.
  • Integrates with Shield (DDoS) and WAF at the edge, and with ACM for HTTPS.
  • CloudFront vs S3 Cross-Region Replication: CloudFront caches everywhere for a set time (TTL); CRR keeps a full, near real-time copy in a few chosen Regions.

AWS Global Accelerator and S3 Transfer Acceleration

  • Global Accelerator: gives your app 2 static anycast IP addresses. User traffic enters AWS at the nearest edge and travels on the private AWS network to your app in one or more Regions. It does not cache. It works for any TCP or UDP app and gives fast Regional failover.
  • S3 Transfer Acceleration: speeds up long-distance uploads to one S3 bucket through edge locations.

EC2 and purchasing options

Amazon EC2 rents you virtual servers (instances). You choose the operating system, the size, the storage and the firewall. It is IaaS, so you manage the OS. Choosing the right pricing option for a workload is one of the most tested skills.

Building an instance

  • AMI (Amazon Machine Image): the template with the OS and software. It can come from AWS, from you, or from AWS Marketplace. AMIs are Regional; copy them to use in another Region. EC2 Image Builder automates creating and testing AMIs.
  • Instance type: m5.2xlarge = class m, generation 5, size 2xlarge.
  • Families: General purpose (balanced, web servers) · Compute optimized (batch, gaming, HPC, transcoding) · Memory optimized (in-memory databases, big caches) · Storage optimized (high local disk I/O, data warehouses, OLTP) · Accelerated computing (GPUs for ML).
  • User Data: a script that runs once at first boot as root to install software.
  • Security groups: the instance firewall. Allow rules only; stateful. A timeout means a security group problem; connection refused means the app isn't running.
  • Ports: 22 SSH (Linux) · 3389 RDP (Windows) · 80 HTTP · 443 HTTPS · 21 FTP.
  • EC2 Instance Connect: SSH from the browser without managing keys (port 22 must still be open). Session Manager (Systems Manager) needs no open ports at all.
  • Elastic IP: a fixed public IPv4 address you keep across stop and start.

Amazon S3

Amazon S3 is object storage with no size limit, used for backups, data lakes, static websites and media. You store objects (files) in buckets. It is designed for 11 nines of durability. Expect several questions on storage classes and security.

Buckets and objects

  • A bucket is created in one Region. By default its name must be globally unique: lowercase, no underscores, not an IP address.
  • An object has a key (its full path, like photos/2025/cat.jpg), the data, metadata and tags. S3 has no real folders.
  • Max object size is 50 TB (raised from 5 TB in December 2025). Uploads over 5 GB must use multipart upload.
  • Durability of 99.999999999% (11 nines) for every class. Availability varies by class (Standard 99.99%).

Security

  • IAM policies (user-based) and bucket policies (resource-based; used for public access, cross-account access, forcing encryption).
  • Access is allowed if an IAM policy or the bucket policy allows it, and nothing explicitly denies it.
  • Block Public Access stops accidental public buckets and can be set for the whole account.
  • Encryption: SSE-S3 on by default for new objects. SSE-KMS for key control and auditing. Client-side if you must encrypt before upload.
  • Pre-signed URL: temporary access to one private object, without making it public.
  • MFA Delete (enabled by the root user) requires MFA to permanently delete versions.

Durability vs availability. Durability (11 nines, the same for every class) is about not losing data. Availability (99.5% to 99.99%) is about being able to reach it right now. Versioning vs Object Lock: versioning keeps old copies but an admin can still delete them; Object Lock prevents deletion.

Memory hook

Minimum durations go 0 → 30 → 90 → 180 days as the classes get colder. Glacier retrieval gets slower as it gets colder: Instant (ms) → Flexible (minutes to hours) → Deep Archive (half a day to two days).

Databases and analytics

AWS has a purpose-built database for each kind of data. The exam describes the data (tables, key-value, JSON documents, graphs, time series) or the job (transactions, analytics, caching) and asks which service fits. Managed databases mean AWS handles patching, backups and high availability.

Relational (SQL)

Monitoring and observability

Monitoring tells you how your systems perform, who changed what, and whether AWS itself has a problem that affects you. The key skill is picking the right tool among CloudWatch, CloudTrail, Config, X-Ray and the Health Dashboard.

Amazon CloudWatch

  • Metrics: numbers over time for every service: EC2 CPU, network, status checks (every 5 minutes by default, every 1 minute with detailed monitoring). EC2 memory is not collected by default; install the CloudWatch agent.

Pricing models and free tier

AWS pricing follows a few simple rules: pay for what you use, pay less when you commit, and pay less when you use more. The exam checks that you can pick the cheapest option that still meets the requirement.

The pricing principles

  • Pay as you go: no upfront cost, no long-term contract.
  • Save when you commit: Reserved Instances (EC2, RDS, ElastiCache, Redshift, OpenSearch), DynamoDB reserved capacity, and Savings Plans.

Accounts and governance

Large companies run many AWS accounts, for example one per team or per environment. AWS Organizations groups them, gives one bill, and applies guardrails. Control Tower sets all of this up the right way.

AWS Organizations

  • One management account and many member accounts, grouped into organizational units (OUs) such as Dev, Prod or Finance.
  • Consolidated billing: one bill and one payment method. Usage is combined for volume discounts, and Reserved Instance and Savings Plans discounts are shared across accounts. It is free.
  • Service control policies (SCPs): guardrails that set the maximum permissions for accounts or OUs, for example “nobody may use services outside eu-west-1.” They apply to every user and role in a member account, including its root user. They don't apply to the management account, and they never grant permissions by themselves.

Cheat sheet

The numbers, rules and one-line matches that show up again and again. If a line here surprises you, open its chapter.

Numbers to remember

  • S3 durability 11 nines (99.999999999%); S3 Standard availability 99.99%
  • S3 max object 50 TB; multipart required above 5 GB
  • S3 minimum storage: IA 30 days · Glacier Instant/Flexible 90 · Deep Archive 180
  • Deep Archive retrieval 12–48 h; Flexible 1 min–12 h; Instant ms
  • AZs per Region: usually 3 (min 3, max 6); edge locations 400+
  • Lambda: max 15 min, up to 10 GB memory; free 1M requests/month
  • SQS retention 4 days default, 14 days max
  • CloudTrail event history 90 days; EC2 metrics every 5 min (1 min detailed)
  • RDS read replicas: up to 15
  • Spot up to 90% off; RIs / EC2 Instance SP up to 72%; Compute SP up to 66%
  • Shield Advanced $3,000/month per organization
  • Ports: 22 SSH · 3389 RDP · 80 HTTP · 443 HTTPS
  • Exam: 65 questions, 90 min, pass 700/1,000, retake after 14 days
