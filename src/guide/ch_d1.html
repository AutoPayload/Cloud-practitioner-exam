Cloud concepts and economics

Must know Read the whole chapter.

Cloud computing is renting IT (servers, storage, databases, software) over the internet and paying only for what you use. AWS owns and runs the hardware. You create and delete resources in minutes, whenever you need them.

The five characteristics of cloud computing

CharacteristicWhat it means in plain words
On-demand self-serviceYou create resources yourself, any time, without calling or emailing the provider.
Broad network accessYou reach the resources over the network from any device: laptop, phone, server.
Multi-tenancy and resource poolingMany customers share the same physical hardware, but each one is isolated and private.
Rapid elasticity and scalabilityResources grow and shrink quickly and automatically with demand.
Measured serviceUsage is metered, so you pay exactly for what you used.

The six advantages of cloud computing

This list is tested almost word for word. Learn to recognize each one from a short story.

Deployment models

Public cloud

Run by a provider such as AWS and used over the internet. It delivers all six advantages.

Private cloud

Used by one organization only and not exposed to the public. Full control, but none of the economies of scale.

Hybrid cloud

Part stays on premises and part runs in the cloud, connected together. It is common during long migrations or for compliance.

Service models: who manages what

Each model moves more layers from you to the provider. The more the provider manages, the less you control and the less you have to operate.

Scalability, elasticity, high availability and agility

  • Vertical scaling (scale up or down): make one instance bigger, for example t2.micro → t2.large. It is common for databases and is limited by hardware.
  • Horizontal scaling (scale out or in): add or remove instances. It is how modern web apps scale, using an Auto Scaling group and a load balancer.
  • Elasticity: scaling that happens automatically with demand, so you pay only for what you need at each moment.
  • High availability: the app keeps running when a data center fails. The minimum is running in at least two Availability Zones.
  • Fault tolerance: the system keeps working with no interruption even when a component fails. It is a stronger promise than high availability.
  • Agility: new resources are a click away, so experimenting is fast and cheap. This is about speed, not about load.

Cloud economics

  • You pay for three things: compute time, data stored, and data transferred out. Data transferred in is free.
  • Fixed vs variable costs: on premises you buy hardware up front (a fixed cost you pay even when it sits idle). On AWS most costs are variable and follow usage.
  • Total cost of ownership (TCO): on premises you also pay for power, cooling, rent, hardware refreshes and the staff who run them. The cloud removes most of these indirect costs.
  • Licensing: either license included (the software cost is part of the hourly price) or bring your own license (BYOL, reuse licenses you already own; server-bound licenses often need Dedicated Hosts).
  • Right sizing: pick the smallest instance that does the job, and keep checking. It is the easiest way to cut costs.
  • Managed services and automation reduce operational cost, because AWS does the patching, backups and scaling.

Well-Architected Framework

Must know Read the whole chapter.

AWS's checklist for building good systems in the cloud. It has six pillars. Exam questions describe a practice and ask which pillar it belongs to, so learn the keywords of each pillar.

The six pillars and their keywords

PillarGoalKeywords that point to it
Operational ExcellenceRun and monitor systems, and keep improving processes.operations as code, small reversible changes, runbooks, learn from failures, observability, CloudFormation
SecurityProtect data, systems and assets.strong identity foundation, least privilege, traceability, encryption at rest and in transit, security at every layer, incident response
ReliabilityRecover from failures and meet demand.recover automatically, test recovery, scale horizontally, stop guessing capacity, multi-AZ, backups, service quotas
Performance EfficiencyUse resources efficiently as needs and technology change.right resource type, serverless, go global in minutes, experiment more often, democratize advanced technology, mechanical sympathy
Cost OptimizationDeliver value at the lowest price.pay for use, measure efficiency, analyze and attribute spend (tags), Savings Plans, Spot, stop spending on data centers
SustainabilityReduce environmental impact.maximize utilization, reduce idle resources, efficient hardware (Graviton), managed services, move cold data, carbon footprint

General design principles

  • Stop guessing capacity. Test systems at production scale.
  • Automate to make experiments easy. Allow evolutionary architectures that change over time.
  • Drive architectures with data. Improve through game days (simulated events such as a flash sale).
  • Cloud design principles: scalability, disposable resources (servers are replaceable), automation, loose coupling (a failure in one part doesn't break the rest), and services, not servers (prefer managed services).

Tools

  • AWS Well-Architected Tool: free. You answer questions about a workload and get a report of risks per pillar with advice.
  • AWS Customer Carbon Footprint Tool: tracks and forecasts the carbon emissions of your AWS usage.

Reliability vs Performance Efficiency. Reliability is about surviving failures and meeting demand. Performance Efficiency is about choosing the right, efficient resources. Scalability is not a pillar. It is a common distractor.

Memory hook

“SPORCS”: Security, Performance efficiency, Operational excellence, Reliability, Cost optimization, Sustainability. One letter per pillar.

Cloud adoption and migration

Must know Read the whole chapter.

How a company moves to AWS. The Cloud Adoption Framework (CAF) organizes the people and process side. The 7 Rs are the options for each application. A set of migration services does the technical work.

AWS Cloud Adoption Framework (CAF): six perspectives

Business perspectives

Business: cloud investments drive business outcomes. People: culture, organizational structure, leadership, workforce and training. Governance: orchestrate initiatives, maximize benefits, minimize risk.

Technical perspectives

Platform: build a scalable hybrid cloud platform and modernize workloads. Security: confidentiality, integrity and availability of data and workloads. Operations: deliver cloud services at the level the business needs.

  • Transformation domains: Technology, Process, Organization, Product.
  • Transformation phases, in order: Envision (find opportunities) → Align (find capability gaps, create an action plan) → Launch (pilots in production) → Scale (expand the pilots).
  • Business outcomes AWS promises: reduced business risk, improved ESG (environmental, social and governance) performance, increased revenue, increased operational efficiency.

The 7 Rs of migration

StrategyWhat you doTypical example
RetireTurn it off. Nobody needs it.An old reporting app nobody opens
RetainKeep it where it is for now.A mainframe with unresolved dependencies
RelocateMove it to the cloud version of the same platform.VMware vSphere → VMware Cloud on AWS
Rehost (“lift and shift”)Move it as it is.Physical server → EC2 with Application Migration Service
Replatform (“lift and reshape”)Move it with a few cloud optimizations.Self-managed MySQL → Amazon RDS
Repurchase (“drop and shop”)Replace it with a different product, often SaaS.On-premises CRM → Salesforce
Refactor / re-architectRedesign it to be cloud native.Monolith → microservices and serverless
