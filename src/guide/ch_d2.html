Shared responsibility model

Must know Read the whole chapter.

Security on AWS is split in two. AWS secures the cloud itself: the buildings, hardware and global network. You secure what you put in the cloud: your data, your users, your settings. This model is behind many exam questions.

Who does what, service by service

ServiceAWS is responsible forYou are responsible for
EC2 (IaaS)Hardware, host isolation, hypervisor, replacing faulty hardwareGuest OS patches, installed software, security groups, IAM roles, data on the instance
EBS, EFS, instance storeInfrastructure, replicating EBS and EFS data, replacing hardwareBackups and snapshots, encryption, understanding that instance store is temporary
RDS (managed)Underlying instance (no SSH), OS and database patching, disksSecurity group rules, database users and permissions, public vs private access, encryption setting, SSL
S3Durability, availability, infrastructure, keeping employees out of your dataBucket policies, Block Public Access, versioning, encryption choice, IAM access
Lambda (serverless)Servers, OS, runtime patching, scalingYour code, its IAM permissions, the data it handles
OutpostsThe rack's hardware and softwarePhysical security of the rack in your data center
  • Shared controls (both sides do their part): patch management, configuration management, awareness and training.
  • Inherited controls (fully AWS): physical and environmental controls of the data centers.
  • Compliance: AWS infrastructure is certified (PCI DSS, ISO, SOC), but your workload is not automatically compliant. You must configure it correctly.

Memory hook

AWS is responsible OF the cloud: think “Own the Facilities.” You are responsible IN the cloud: everything you put IN. If you can configure it, it is your responsibility.

Don't confuse

The AWS Acceptable Use Policy says what you must not do on AWS (spam, attacks, illegal content). The shared responsibility model says who secures what. They are different documents.

IAM and identity

Must know Read the whole chapter.

AWS Identity and Access Management (IAM) controls who can do what in your account. It is a global service and it is free. On top of IAM, AWS offers services for app users, single sign-on and temporary access.

The building blocks

ItemWhat it isRemember
Root userThe account owner, created with the account. It has full access.Enable MFA, lock it away, don't use it daily, don't create access keys for it
IAM userOne person (or app) with long-term credentials.One physical person = one IAM user
IAM groupA collection of users. Permissions attached to the group apply to its members.Groups contain users only, never other groups
IAM rolePermissions that a service or user assumes temporarily.Use roles for EC2, Lambda and cross-account access. No stored keys.
IAM policyA JSON document that allows or denies actions on resources.An explicit Deny always wins over an Allow

A policy is a JSON document. Each statement has an Effect (Allow or Deny), an Action (such as s3:GetObject) and a Resource.

Ways to access AWS

MethodProtected by
AWS Management Console (web)Password + MFA
AWS CLI (command line)Access keys (access key ID ≈ username, secret access key ≈ password)
AWS SDKs (code, e.g. Python Boto3)Access keys, or a role when the code runs on AWS
AWS CloudShell (browser terminal)Your console sign-in; the CLI is preinstalled

MFA devices: an authenticator app on a phone, a security key (such as YubiKey), or a hardware key fob.

Best practices and audit tools

  • Use the root user only for account setup and root-only tasks. Enable MFA everywhere.
  • Give least privilege. Put users in groups and attach policies to groups.
  • Use a strong password policy (length, character types, expiration, no reuse).
  • Use roles for AWS services. Never put access keys in code or on an instance.
  • IAM Credentials Report (account level): every user and the status of their passwords, keys and MFA.
  • IAM Access Advisor (user level): which services a user can access and when each was last used. Use it to remove unused permissions.

Root-only tasks: change account settings (name, email, root password, root access keys), close the account, restore IAM user permissions, turn on IAM access to the Billing console, view certain tax invoices, register as a seller in the Reserved Instance Marketplace, enable MFA Delete on an S3 bucket, edit a bucket policy that locks everyone out, sign up for GovCloud.

Changing the Support plan is no longer root-only: an IAM user with the right permissions can do it.

Network and application protection

Must know Read the whole chapter.

These services keep attackers away from your applications: firewalls at different layers, DDoS protection, and central management of all those rules. The exam also tests what you may and may not do when you security-test your own resources.

Firewalls from the instance to the whole organization

ControlProtectsKey facts
Security groupAn instance (its network interface)Allow rules only, stateful (return traffic allowed), default: all inbound blocked, all outbound allowed
Network ACL (NACL)A subnetAllow and deny rules, stateless (return traffic must be allowed too), rules by IP
AWS WAFWeb apps on ALB, API Gateway, CloudFrontLayer 7 (HTTP). Blocks SQL injection and cross-site scripting. Geo-blocking and rate-based rules
AWS Network FirewallA whole VPCLayers 3–7, inbound, outbound, VPC to VPC, VPN and Direct Connect traffic
AWS Firewall ManagerAll accounts in an organizationCentral management of WAF rules, security groups, Shield Advanced and Network Firewall; applies to new resources automatically

DDoS protection

  • AWS Shield Standard: free and automatic for every customer. Protects against common layer 3 and 4 attacks (SYN floods, UDP reflection).
  • AWS Shield Advanced: a paid subscription. Adds protection for EC2, ELB, CloudFront, Global Accelerator and Route 53, 24/7 access to the Shield Response Team, and cost protection against bills caused by a DDoS attack.
  • Best architecture against DDoS: put CloudFront and Route 53 in front (they absorb attacks at the edge), add WAF for layer 7, and scale with Auto Scaling.

Penetration testing and abuse

  • You may test your own EC2, NAT gateways, ELB, RDS, Aurora, CloudFront, API Gateway, Lambda, Lightsail and Elastic Beanstalk without asking AWS.
  • You may not run DoS or DDoS attacks (even simulated), port flooding, protocol flooding, request flooding, or DNS zone walking on Route 53 hosted zones.
  • If AWS resources attack you (spam, port scans, DDoS, malware), report it with the AWS Abuse form (Trust & Safety team).
  • The AWS Acceptable Use Policy lists what nobody may do on AWS.

If the question saysThink

Don't confuse

Shield vs WAF. Shield stops floods of traffic (DDoS, layers 3 and 4). WAF inspects web requests (layer 7) and blocks attacks hidden inside them, like SQL injection. WAF cannot be attached to a Network Load Balancer or directly to EC2.

Memory hook

A security group is a door guard with a guest list: only allow rules, and once you are in you can leave freely (stateful). A NACL is a border checkpoint: it can deny, and it checks you both ways (stateless).

Encryption and secrets

Must know Read the whole chapter.

Encryption protects data when it is stored (at rest) and when it moves across the network (in transit). On the exam, the word “encryption” usually points to AWS KMS. Certificates for HTTPS come from ACM, and passwords belong in Secrets Manager or Parameter Store.

Key facts

  • At rest: data on a disk, in S3, in a database or an archive. In transit: data moving over the network, protected with TLS (HTTPS).
  • Encryption on by default: CloudTrail logs, S3 Glacier storage classes, Storage Gateway, and since 2023 every new S3 object (SSE-S3).
  • Opt-in encryption: EBS volumes, RDS, EFS, and SSE-KMS for S3.
  • S3 options: SSE-S3 (default, S3-managed keys), SSE-KMS (KMS keys with audit trail), SSE-C (your own key sent with each request), client-side (you encrypt before upload).

The services

ServiceWhat it doesPick it when
AWS KMSCreates and manages encryption keys. Integrated with most services. AWS runs the hardware and software.“Encrypt data at rest,” “manage encryption keys,” “rotate keys”
AWS CloudHSMA dedicated hardware security module. You fully manage the keys; AWS can't see them. FIPS 140-2 Level 3.“Dedicated hardware,” “single tenant,” “we must control the keys ourselves”
AWS Certificate Manager (ACM)Free public SSL/TLS certificates with automatic renewal, for ELB, CloudFront and API Gateway.“HTTPS,” “SSL/TLS certificate,” “encryption in transit”
AWS Secrets ManagerStores secrets and rotates them automatically (built-in for RDS). Paid per secret.“Rotate database credentials every 30 days”
SSM Parameter StoreStores configuration values and secrets, optionally encrypted with KMS. Free standard tier, no built-in rotation.“Store configuration and secrets centrally at low cost”

KMS key types: customer managed (you create and control them, including rotation) and AWS managed (AWS creates and manages them for a service in your account).

How the exam asks about it

If the question saysThink
managed service to create and control encryption keysAWS KMS
FIPS 140-2 Level 3, dedicated, customer-controlled keysAWS CloudHSM
free SSL/TLS certificate for a load balancerAWS Certificate Manager

Don't confuse

KMS vs CloudHSM: KMS is shared, fully managed and the default answer. CloudHSM is dedicated hardware and you do the key management. Secrets Manager vs Parameter Store: both store secrets, but only Secrets Manager rotates them automatically.

Detection, audit and compliance

Must know Read the whole chapter.

Many security questions are “pick the right service” questions, and these services sound alike. Learn one sharp sentence for each one and you will get most of these questions right.

One sentence per service

ServiceWhat it does
AWS CloudTrailRecords every API call: who did what, when, from where. On by default (90 days of event history). “Something was deleted” → check CloudTrail.
AWS ConfigRecords resource configuration over time and checks it against rules (“is SSH open to the world?”, “which buckets are public?”).
Amazon GuardDutyThreat detection with ML from CloudTrail, VPC Flow Logs and DNS logs. One click, no agents. Finds crypto mining and compromised instances.
Amazon InspectorVulnerability scanning (CVEs) of EC2 instances, ECR container images and Lambda functions.
Amazon MacieFinds sensitive data (PII) in S3 buckets using ML.
AWS Security HubOne dashboard for security findings from many services and accounts, plus automated best-practice checks (needs AWS Config).
Amazon DetectiveInvestigates the root cause of findings with graphs and ML.
IAM Access AnalyzerFinds resources shared outside your account or organization (S3 buckets, roles, KMS keys).
AWS ArtifactDownloads AWS compliance reports (SOC, PCI, ISO) and accepts agreements like the HIPAA BAA.
AWS Trusted AdvisorChecks your account against best practices, including security checks such as open ports, root MFA and public buckets.

Where to find security information: the AWS Security Center (aws.amazon.com/security), the AWS Security Blog, the Knowledge Center and re:Post. Third-party security tools are sold in AWS Marketplace.

How the exam asks about it

If the question saysThink
who deleted the bucket? which user made the API call?CloudTrail
how did this resource's configuration change over time?AWS Config
detect malicious activity, compromised instancesGuardDuty
software vulnerabilities, CVEs, container image scanningInspector

Don't confuse
  • CloudTrail vs Config vs CloudWatch. CloudTrail = who did it (API calls). Config = what the resource looks like and looked like. CloudWatch = how it performs (metrics, logs, alarms).
  • GuardDuty vs Inspector. GuardDuty watches behavior (logs) for attacks happening now. Inspector scans software for known weaknesses before they are exploited.
  • Artifact vs Config. Artifact gives AWS's compliance reports. Config checks your resources' compliance.
Memory hook

Macie sounds like “my PII.” Inspector inspects software. GuardDuty is the guard on duty watching for intruders. Detective finds out why. Artifact is the museum of AWS certificates.
