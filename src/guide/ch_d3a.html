Global infrastructure

Must know Read the whole chapter.

AWS is built from Regions, and each Region contains several Availability Zones. Edge locations around the world bring content close to users. Local Zones, Wavelength and Outposts extend AWS closer to cities, 5G networks and your own data center.

Key facts

  • Region: a geographic area with a cluster of data centers, named like us-east-1. Most services are Regional. Your data never leaves a Region unless you move it.
  • Choosing a Region: (1) compliance and data residency, (2) latency to your users, (3) which services are available there, (4) price.
  • Availability Zone (AZ): one or more separate data centers with their own power and networking. A Region usually has 3 (minimum 3, maximum 6). Running in two or more AZs gives high availability.
  • Edge locations (points of presence): 400+ sites that cache content (CloudFront) and answer DNS (Route 53) close to users.
  • Global services: IAM, Route 53, CloudFront, WAF (for CloudFront). Everything else you create in a Region.
  • AWS Local Zones: AWS compute and storage placed near a large city for single-digit millisecond latency. They extend a Region.
  • AWS Wavelength: AWS compute inside telecom 5G networks for ultra-low latency to mobile devices.
  • AWS Outposts: AWS-managed racks installed in your data center, with the same APIs and tools. You handle the rack's physical security.

Designing for failure

ArchitectureSurvivesTrade-off
One Region, one AZNothing: a data center failure stops the appSimplest and cheapest
One Region, multiple AZsLoss of a data center or AZThe standard for high availability
Multiple Regions, active-passiveLoss of a whole Region (failover)More cost; writes go to one Region
Multiple Regions, active-activeRegion loss, with low latency everywhereMost complex and expensive

Disaster recovery strategies, from cheapest and slowest to most expensive and fastest: Backup and restore → Pilot light (core pieces running, like a live database copy) → Warm standby (a full copy running at small size) → Multi-site active-active (full size in two Regions). RPO is how much data you can lose; RTO is how long you can be down.

DNS, content delivery and edge

Skim Read the “How the exam asks” table first. Read the rest only if something there surprises you.

These services make a global application fast and resilient. Route 53 tells users where to go. CloudFront caches content near them. Global Accelerator routes their traffic over the AWS network.

Amazon Route 53 (DNS)

  • Managed DNS and domain registration. Translates names like app.example.com into IP addresses. It is a global service with health checks.
  • Routing policies: Simple, Weighted (split traffic 70/30), Latency-based (send users to the fastest Region), Failover (health check fails → go to the backup), plus Geolocation, Geoproximity and Multivalue.

Amazon CloudFront (CDN)

  • Caches content at 400+ edge locations so users download it from nearby. It is good for images, video, static sites and APIs.
  • Origins: an S3 bucket (protected with Origin Access Control so only CloudFront can read it), a load balancer, EC2, or any HTTP server.
  • Integrates with Shield (DDoS) and WAF at the edge, and with ACM for HTTPS.
  • CloudFront vs S3 Cross-Region Replication: CloudFront caches everywhere for a set time (TTL); CRR keeps a full, near real-time copy in a few chosen Regions.

AWS Global Accelerator and S3 Transfer Acceleration

  • Global Accelerator: gives your app 2 static anycast IP addresses. User traffic enters AWS at the nearest edge and travels on the private AWS network to your app in one or more Regions. It does not cache. It works for any TCP or UDP app and gives fast Regional failover.
  • S3 Transfer Acceleration: speeds up long-distance uploads to one S3 bucket through edge locations.

Don't confuse

CloudFront vs Global Accelerator. Both use edge locations. CloudFront caches content (HTTP). Global Accelerator doesn't cache; it gives static IPs and a fast path for any TCP/UDP traffic.

EC2 and purchasing options

Must know Read the whole chapter.

Amazon EC2 rents you virtual servers (instances). You choose the operating system, the size, the storage and the firewall. It is IaaS, so you manage the OS. Choosing the right pricing option for a workload is one of the most tested skills.

Building an instance

  • AMI (Amazon Machine Image): the template with the OS and software. It can come from AWS, from you, or from AWS Marketplace. EC2 Image Builder automates creating and testing AMIs.
  • Families: General purpose (balanced, web servers) · Compute optimized (batch, gaming, HPC, transcoding) · Memory optimized (in-memory databases, big caches) · Storage optimized (high local disk I/O, data warehouses, OLTP) · Accelerated computing (GPUs for ML).
  • User Data: a script that runs once at first boot as root to install software.
  • Security groups: the instance firewall. Allow rules only; stateful.
  • Ports: 22 SSH (Linux) · 3389 RDP (Windows) · 80 HTTP · 443 HTTPS.
  • Session Manager (part of Systems Manager) gives a shell on the instance with no open ports and no SSH keys. EC2 Instance Connect is SSH from the browser, so port 22 must be open.
  • Elastic IP: a fixed public IPv4 address you keep across stop and start.

Load balancing and Auto Scaling

Skim Read the “How the exam asks” table first. Read the rest only if something there surprises you.

A load balancer spreads traffic across many instances and skips unhealthy ones. An Auto Scaling group adds and removes instances as demand changes. Together, across several AZs, they give you high availability and elasticity.

Elastic Load Balancing

TypeLayerUse it for
Application Load Balancer (ALB)7HTTP, HTTPS, gRPC. Routing by URL path or host name. Works with WAF.
Network Load Balancer (NLB)4TCP and UDP, millions of requests per second, ultra-low latency, static IP.
Gateway Load Balancer (GWLB)3Sending traffic through third-party firewalls and inspection appliances.
Classic Load Balancer4 and 7Previous generation. Don't pick it for new workloads.

Why use ELB: one DNS name for users, health checks, spreads load across AZs, HTTPS termination with ACM certificates, and AWS manages it (upgrades, scaling, availability).

Auto Scaling groups

  • Keep the instance count between a minimum and a maximum, around the desired capacity. Replace unhealthy instances automatically.
  • Scaling policies: target tracking (keep average CPU at 40%) · scheduled (every Friday at 5 PM) · predictive (ML forecasts daily and weekly patterns) · manual.

Don't confuse

A load balancer spreads traffic but never adds instances. Auto Scaling adds and removes instances but doesn't spread traffic. You need both for an elastic, highly available web app.

Containers and serverless

Must know Read the whole chapter.

Containers package an app with everything it needs so it runs the same everywhere. Serverless means you run code or containers without managing any servers, and you pay only while they run.

Containers on AWS

ServiceWhat it does
Amazon ECSAWS's own service to run Docker containers. With the EC2 launch type you manage the instances.
AWS FargateRuns containers serverless: you set CPU and memory, AWS runs the infrastructure. Works with ECS and EKS.
Amazon EKSManaged Kubernetes, the open-source orchestrator. Pick it when a company already uses Kubernetes or wants portability.
Amazon ECRPrivate registry to store your container images.

Serverless compute

  • AWS Lambda: runs functions in response to events (an S3 upload, an API call, a schedule). Scales automatically. Max 15 minutes per run, up to 10 GB memory. You pay per request and per millisecond of run time; the free tier includes 1 million requests per month.
  • Amazon API Gateway: create, publish and secure APIs (REST, WebSocket). The classic serverless pattern is API Gateway → Lambda → DynamoDB.
  • Serverless examples: Lambda, Fargate, S3, DynamoDB, API Gateway, SQS, SNS, Aurora Serverless.

Other compute

  • AWS Batch: runs large numbers of batch jobs (with a start and an end), no time limit, on EC2 or Spot, packaged as containers.
  • Amazon Lightsail: simple virtual servers, databases and networking with low, predictable monthly prices. For people with little cloud experience, such as a small WordPress site. No auto scaling.
