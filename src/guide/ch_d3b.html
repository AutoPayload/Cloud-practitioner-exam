EBS, EFS and FSx

Skim Read the “How the exam asks” table first. Read the rest only if something there surprises you.

Storage for your servers comes in three shapes. Block storage is a disk for one instance (EBS, instance store). File storage is a shared folder for many instances (EFS, FSx). Object storage holds files reached over the web (S3). Pick by how the data is used.

The options

ServiceTypeKey facts
Amazon EBSBlock (network disk)Attached to one instance at a time. Locked to one AZ: to move it, take a snapshot. Keeps data after the instance stops.
EBS snapshotsBackupPoint-in-time backups. You can copy them to another AZ or Region.
EC2 instance storeBlock (physical disk)The fastest I/O, but temporary: data is lost when the instance stops or fails. Use it for caches and scratch data.
Amazon EFSFile (NFS, Linux)Shared by hundreds of instances across AZs. Grows and shrinks automatically, pay per use. EFS-IA with a lifecycle policy saves up to 92% on rarely used files.
FSx for Windows File ServerFile (SMB, Windows)Windows shares with NTFS and Active Directory integration.
FSx for LustreFile (HPC, Linux)Very high performance for HPC and ML. Integrates with S3.
FSx for NetApp ONTAP / OpenZFSFileManaged versions of those popular file systems, for easy migration.

Memory hook

EBS = Block = a USB stick for one computer. EFS = File = a shared Folder for many. S3 = a giant bucket of objects on the web.

Amazon S3

Must know Read the whole chapter.

Amazon S3 is object storage with no size limit, used for backups, data lakes, static websites and media. You store objects (files) in buckets. It is designed for 11 nines of durability. Expect several questions on storage classes and security.

Buckets and objects

  • A bucket is created in one Region, but by default its name must be unique across all AWS accounts.
  • An object has a key (its full path, like photos/2025/cat.jpg), the data, metadata and tags. S3 has no real folders.
  • Max object size is 50 TB (it was 5 TB until December 2025, so older questions may say 5 TB). Big files are uploaded in parts (multipart upload).
  • Durability of 99.999999999% (11 nines) for every class. Availability varies by class (Standard 99.99%).

Security

  • IAM policies (user-based) and bucket policies (resource-based; used for public access, cross-account access, forcing encryption).
  • Access is allowed if an IAM policy or the bucket policy allows it, and nothing explicitly denies it.
  • Block Public Access stops accidental public buckets and can be set for the whole account.
  • Encryption: SSE-S3 on by default for new objects. SSE-KMS for key control and auditing. Client-side if you must encrypt before upload.
  • Pre-signed URL: temporary access to one private object, without making it public.
  • MFA Delete (enabled by the root user) requires MFA to permanently delete versions.

Features

FeatureWhat it does
VersioningKeeps every version of an object. Protects against accidental deletes and overwrites.

Don't confuse

Durability vs availability. Durability (11 nines, the same for every class) is about not losing data. Availability (99.5% to 99.99%) is about being able to reach it right now. Versioning vs Object Lock: versioning keeps old copies but an admin can still delete them; Object Lock prevents deletion.

Memory hook

Minimum durations go 0 → 30 → 90 → 180 days as the classes get colder. Glacier retrieval gets slower as it gets colder: Instant (ms) → Flexible (minutes to hours) → Deep Archive (half a day to two days).

Hybrid storage, transfer and backup

Skim Read the “How the exam asks” table first. Read the rest only if something there surprises you.

These services connect your data center to AWS storage, move large amounts of data into AWS, and protect your data with backups and disaster recovery.

Moving and bridging data

ServiceUse it when
AWS Snowball EdgeMoving terabytes to petabytes offline on a shipped device, when the network would take more than a week. It can also run EC2 and Lambda at the edge (ships, mines, trucks).
AWS DataSyncMoving large data online from on-premises NFS/SMB storage to S3, EFS or FSx, on a schedule, copying only changes after the first run.
AWS Storage GatewayOn-premises apps need to keep using cloud storage through standard protocols: File Gateway (files in S3), Volume Gateway (block volumes backed by S3), Tape Gateway (virtual tapes to replace physical backup tapes).
AWS Transfer FamilyPartners must upload files over SFTP, FTPS or FTP directly into S3 or EFS.

Rule of thumb: if moving the data over the network would take more than a week, use Snowball.

Backup and disaster recovery

  • AWS Backup: one place to define backup plans (schedule, retention, lifecycle) for EC2, EBS, S3, RDS, Aurora, DynamoDB, EFS, FSx and Storage Gateway. It works across Regions and across accounts.
  • AWS Elastic Disaster Recovery (DRS): continuously replicates physical, virtual or cloud servers into AWS and fails over in minutes. It is good for ransomware recovery.

Databases and analytics

Must know Read the whole chapter.

AWS has a purpose-built database for each kind of data. The exam describes the data (tables, key-value, JSON documents, graphs, time series) or the job (transactions, analytics, caching) and asks which service fits. Managed databases mean AWS handles patching, backups and high availability.

Relational (SQL)

  • Amazon RDS: managed PostgreSQL, MySQL, MariaDB, Oracle, SQL Server, Db2. Automated backups, point-in-time restore, patching. No SSH access. Used for OLTP (transactions).
  • RDS Multi-AZ: a standby copy in another AZ with automatic failover. It is for high availability, not for reads.
  • RDS read replicas: up to 15 read-only copies to scale reads. They can be in other Regions.
  • Amazon Aurora: AWS's own MySQL- and PostgreSQL-compatible engine. Up to 5× faster than MySQL on RDS, storage grows automatically, data is copied across 3 AZs. Aurora Serverless scales automatically for intermittent or unpredictable workloads.

Don't confuse
  • Multi-AZ vs read replicas. Multi-AZ is for availability (failover). Read replicas are for performance (more reads).
  • RDS vs Redshift. RDS runs the app's day-to-day transactions (OLTP). Redshift runs big analytic queries over history (OLAP).
  • Athena vs Redshift. Athena queries files in S3 with no infrastructure. Redshift is a data warehouse you load data into.
Memory hook

Neptune is the planet with many connections (graph). Timestream = a stream of time. DocumentDB = documents (JSON, MongoDB). Redshift = shift your data to red-hot analytics. Athena, goddess of wisdom, answers questions about S3.
